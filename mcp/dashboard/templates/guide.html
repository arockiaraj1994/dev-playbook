MCP tools at a glance

Three read-only tools, all playbook_-namespaced. playbook_start is the only entry point - it returns identity + guardrails + matched workflow + a single ## Next Calls block of ready-to-paste playbook_get(…) calls.

ToolWhen the agent should call it
playbook_start(project, intent)First call, always. Free-form sentence in; identity + guardrails + definition of done + the matched workflow + a Next Calls list out.
playbook_get(project, ref)Fetch any doc. ref is the same string the corpus uses in see_also: - guardrails, pattern:repository, language:kotlin/testing - so a Next Calls bullet can be followed verbatim.
playbook_find(project, query?, type?)Discovery. Omit query to list docs + triggers; pass query to search. type= restricts to one doc type.

Every doc response that declares see_also: or targets: ends with ## Next Calls rendered as playbook_get(ref=…) - that is how agents chain without guessing paths. project is always required: the basename of the user's workspace directory.

Corpus layout

Docs live under standards/ next to mcp/. The validator enforces the shape; the loader indexes by path; INDEX.md is auto-generated in each project.

Browse health on the dashboard: Standards →. Copy from a live project (standards/nexre/, standards/apache-camel/).

Standards - standards/<project>/

Files marked required are checked by scripts/validate-rules.py --corpus standards.

standards/<your-project>/
├── README.md                          ← humans
├── AGENTS.md                          ← required - AI identity (## IDENTITY + see_also)
├── INDEX.md                           ← auto-generated trigger map (do not hand-edit)
├── core/
│   ├── guardrails.md                  ← required - always-on MUST / MUST NOT
│   ├── definition-of-done.md          ← required - tests + lint + security gates
│   └── glossary.md                    ← required - domain terms
├── architecture/
│   ├── overview.md                    ← required - system overview
│   ├── decisions/                     ← ADRs (one .md per decision)
│   └── diagrams/                      ← optional images
├── languages/
│   └── <lang>/                        ← java | typescript | python | kotlin | …
│       ├── standards.md               ← at least one languages/<lang>/standards.md
│       ├── testing.md
│       └── anti-patterns.md
├── patterns/
│   └── <name>.md                      ← canonical noun-named patterns
├── skills/
│   └── <action>.md                    ← verb-noun playbooks
├── workflows/                         ← all four required
│   ├── new-feature.md
│   ├── bug-fix.md
│   ├── security-fix.md
│   └── refactor.md
└── gates/
    ├── README.md                      ← required - what each gate enforces
    └── scripts/
        └── verify-<lang>.sh           ← executable (chmod +x)

The loader infers doc_type from path. Anything outside the recognized folders lands in other and the validator fails. The corpus is boot-cached - reload it from the Standards page or restart.

Frontmatter that wires the agent

The loader reads optional YAML frontmatter. Load-bearing fields:

  • triggers: - phrases playbook_start matches against the user's task (workflows / skills).
  • see_also: - standards chain. Entries <kind>:<name> become playbook_get(…) in ## Next Calls.
  • gates: - on workflows, names the verify-*.sh script(s) that close the task.
---
title: Workflow - Bug fix
description: Reproducing, isolating, and fixing a defect.
triggers: [bug, fix a bug, debug a route]
gates: [verify-java]
see_also: [skill:debug-route, pattern:error-handling, language:java/testing, core:guardrails]
---

# Workflow - Bug fix

## Steps
1. Reproduce first.
2. ...

Valid kinds: tool, pattern, skill, workflow, gate, language, architecture, core, agents. Valid tool: names: playbook_start, playbook_get, playbook_find, playbook_find, playbook_start (pre-0.7.0 names like start_task still render). Unrecognized entries are a validation error - they would otherwise render as nothing and silently break the chain.

Validate & reload

After adding or editing docs, regenerate INDEX.md and run the validator. CI runs the same check and blocks on failure.

# From repo root (or via: cd mcp && uv run dev.py - regenerates + validates before start)
python scripts/validate-rules.py --regen-index
python scripts/validate-rules.py --check
chmod +x standards/<project>/gates/scripts/verify-*.sh   # if you added a gate

Docs are loaded once at boot. Admins can force a reload from the Standards page without a full restart.

Watch the Searches → Zero-result tab - every entry is a doc your team is asking for. Write it as a workflow, skill, or pattern, and the badge clears once the agent finds it.
